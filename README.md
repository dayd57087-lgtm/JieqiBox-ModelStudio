# 模型工坊（JieqiBox Model Studio）

一个安卓 APK，把「采集 → 标注 → 训练」整条链路装进手机里。用来给揭棋识别模型
攒数据、训模型，不需要电脑。

## 下载

固定地址，每次构建覆盖，链接不变：

```
https://github.com/dayd57087-lgtm/JieqiBox-ModelStudio/releases/download/studio-latest/jieqibox-model-studio.apk
```

零权限：截图走系统文件选择器（SAF）导入，导出走 MediaStore 写进「下载/模型工坊」。

## 三步用法

### 1. 采集

点「导入截图」，从相册里多选对局截图。也可以在游戏里随手截屏，攒一批一起导入。
导入时长边会被压到 1600px 存进应用内数据库（IndexedDB），格子约 160px，够切 32×32 的样本。

> 没有任何截图也没关系：点「生成演示局面」会用内置棋盘图合成 40 个带标注的局面，
> 30 秒就能把整条链路走一遍，确认训练确实能跑出模型。

### 2. 标注

**标定**：进入标注页，在棋盘外沿拖一个框 —— 只需要大致圈住九路十行。
程序会在框内做一维投影拟合，把 9 条竖线 10 条横线精确定位到**亚像素**，
实测四个场景（原图 / 1080×2340 带 UI 栏 / 框选偏小 12% / 框选偏大 20%）误差都 < 0.5% 格。

标定之后再拖是没用的，得先点「框选棋盘」重新进入标定模式。
不满意可以点「微调」平移/缩放，或者「自动校正」以当前结果为起点再拟一次。

**落子**：底部选一个笔刷（帅/仕/相/马/车/炮/兵 / 将/士/象/马/车/炮/卒 / 暗），
然后在盘面上点格子。**同一笔刷再点一次是擦除**，方便改错。
放大后单指拖动是平移，双指捏合缩放；未放大时单指划过可以连续刷同色棋子。

标定完成后画布会自动取景框住棋盘（而不是整张截图），格子约 39px，比按整图缩放清晰一倍多。

**提速**：「复制上局」直接把上一局的标注搬过来 —— 残局之间往往只差几步，改几个格子就行。

### 3. 训练

点「构建数据集」→「开始训练」。

- 按**图片**划分训练/验证（不是按格子），避免同一局面的格子同时出现在两边造成数据泄漏
- 空格默认只保留 30%，否则模型会退化成「全猜空」
- 参考量级：40 张图 / 3600 格，输入 32×32，10 轮约 18 秒，验证集准确率 ~92%

## 导出

训练完会自动把模型存一份在应用里（关掉再打开还能用），另有三个导出按钮：

| 按钮 | 产物 | 用途 |
|---|---|---|
| **保存模型** | `.json` + `.bin` | TF.js layers-model，存进应用同时导出到「下载/模型工坊」 |
| **导出 ONNX** | `.onnx` | 通用格式，任何支持 ONNX 的运行时都能加载 |
| 「模型」页的 **ONNX** | `.onnx` | 对已保存的历史模型补导，不必重新训练 |

### ONNX 的接口约定

```
输入  'input'   [N, H, W, 3]   float32 · NHWC
输出  'logits'  [N, classes]   float32 · 未过 softmax（与 TF.js 模型逐位一致）
```

H 和 W 是训练时选的输入边长（16/24/32/48/64）。图内部开头会转成 NCHW 跑卷积
（ONNX 的 Conv 规范要求），全连接之前再转回 NHWC —— 这一步不能省：
NCHW 展平是 `(c,h,w)` 顺序，而 TF.js 训练时用的是 `(h,w,c)`，直接展平会让权重全部错位。

模型自带元数据，拿到 `.onnx` 的人不必翻源码就知道输出第几维对应哪个棋子：

```
labels = empty,r_general,r_advisor,...,dark
input_size = 32x32
input_layout = NHWC
output = logits (未过 softmax)
grid = 9x10
crop_k = 1.14
```

### 为什么手写 protobuf

tf2onnx / onnx 那套依赖 Python 和完整的 TF 图，在 Android WebView 里跑不起来。
本工坊的模型结构完全已知（就 Conv/Relu/MaxPool/Flatten/Dense 几种层），
手写 protobuf 反而更可靠、体积也更小，还不用多带一个几十兆的依赖。

### 怎么验证导出是对的

`tools/onnx-test.html`：对同一个模型，TF.js 跑一遍、导出的 ONNX 用 onnxruntime-web 跑一遍，
比对输出。权重是随机的 —— 随机的数字让任何下标错位都立刻暴露，比训练过的权重更能查出问题。

实测三档输入尺寸（16/24/32），最大绝对误差 3.4e-7（float32 精度极限），
argmax 完全一致。改完导出器后重新打开这个页面就能回归。

> 踩过的坑：ONNX 的 `ModelProto` 里 **graph 是 field 7、opset_import 是 field 8**。
> 这两个极易记反，而且写错时 protobuf 不会报解析失败（wire type 相同），
> 运行时只会说「No graph was found in the protobuf」，很难定位。

## 怎么判断训得好不好

只有「准确率 92%」这一个数字是没法做决定的。这里给四个层次的证据：

### 1. 训练曲线

结果区那张图是训练 loss 随轮次的变化。看两件事：

- **还在往下降** → 欠拟合，加轮数
- **已经平了** → 再加轮数没用，该加图片了
- **先降后升** → 过拟合，减轮数或加图

### 2. 错分去向

比「哪一类错了」更有用的是「错到哪去了」。比如显示：

```
车 b_chariot → 卒 b_soldier ×11    11/12
```

意思是 12 个黑车里错了 11 个，而且全被认成卒。这种成片混淆通常指向具体原因 ——
棋子被裁切偏了、或者这两类样本都不够。反过来如果错误是零散的，多半只是样本太少。

### 3. 逐图回测

点「逐图回测」，对**每一张**已标注图跑一遍模型，按错误数排序列出，并且把两组分开统计：

| | 含义 |
|---|---|
| **验证图准确率** | 模型没见过的图 —— 这才是真实水平 |
| **训练图准确率** | 模型背下来的图 |

两组差得越多说明越是在背答案。差距 <3 个点算正常，>8 个点会直接标红提示过拟合。

点任意一行会跳到那张图，并把模型预测叠加到棋盘上：**绿圈=判对，红圈=判错**，
红圈里显示的是模型认为的棋子。这样能一眼看出是「框歪了」还是「真认不出」——
如果是前者，整列或整行都错，需要重新标定；如果是后者，错的是零散的某几格。

### 4. 单图检查

标注页的「用模型检查」随时可以对当前图跑一次推理，不必等回测。
提示条会直接告诉你「N 格不符（其中非空 M 格）」。

### 判断该怎么改

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 训练图好、验证图差很多 | 过拟合 | 加图，或减轮数 |
| 两组都差，且错得零散 | 数据不够 | 多标几十张 |
| 两组都差，且整行整列错 | 标定歪了 | 回标注页重新「框选棋盘」 |
| 某一类几乎全错、且都错成同一类 | 该类的样本太少，或裁切偏 | 补该类样本 |
| loss 还一直在降 | 欠拟合 | 加轮数 |

### 模型管理

「模型」页列出所有模型（含训练完自动保存的那份），可以随时**载入并测试**、
**导出**或**删除**。载入后直接就能用「用模型检查」和「逐图回测」，
不需要重新训练。

## 设计取舍

**为什么是逐格分类，不做整图检测。**
棋盘是固定的 9×10 晶格，格子位置能从截图里精确拟合出来，识别问题就退化成
「这一格是什么子」。模型因此小到 94K 参数、手机上几十秒能训完；
端侧训练检测器（YOLO 那种）在 Android 上根本没有成熟栈。

**为什么训练在 WebView 里用 TF.js。**
Kotlin 侧没有能训练检测/分类器的成熟方案（TFLite 的端侧训练只支持冻结主干换分类头）。
TF.js 在 WebGL 后端上跑得动小分类器，而且标注 UI 和训练循环共享同一套数据，
不用来回传。原生壳只负责 WebView 干不了的三件事：https 源托管、SAF 选图、写下载目录。

**标定为什么要自动拟合。**
标注错位会直接毒化训练数据 —— 这是整个流程里最贵的错误。
拟合里有一个反直觉的坑：按「9 条线的平均暗度」打分时，线距缩小会让线挤进深色区域拿到高分，
于是拟合出一组毫无意义的密集线（框选偏小 12% 就会塌缩到 0.67 倍间距）。
所以加了硬约束：整段跨度必须接近用户框选的长度。

## 已知限制

- 训练期间请让应用留在前台。WebView 在后台会节流定时器，训练不会崩，但会明显变慢。
  （训练中会自动保持屏幕常亮。）
- 类别表写死在 `studio.js` 的 `CLASSES`。暗子目前只有一类 `dark`；
  如果实际画面里暗子能区分红黑，把 `dark` 拆成 `dark_r` / `dark_b` 即可。
- 这个模型是给识别管线用的「第二级」分类器。要接进对弈应用，
  运行时需要先用晶格拟合定位棋盘，再逐格分类。
